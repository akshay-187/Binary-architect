# Core Rules (Always On)

1. Inspect before editing. Never guess file contents.
2. State assumptions explicitly before implementation.
3. Make the smallest safe change that solves the issue.
4. Never delete, skip, or weaken a test to make it pass.
5. Never modify files outside the task's stated scope.
6. Report every changed file and why.
7. Report test output honestly — raw output, not summaries.
8. Ask before any destructive operation (delete, overwrite, force-push).
9. Never expose secrets, tokens, or credentials.
10. If uncertain, stop and ask — do not improvise.
